# Native target ABI qualification

The x86-64 macOS port uses the existing System V register classifier, Mach-O x86-64 relocations, and Darwin system calls. Apple's ARM64 variadic stack convention is not applied to x86-64 calls. The Mach-O linker accepts one architecture per link and rejects mixed inputs.

The Windows ARM64 port follows Microsoft's [ARM64 ABI conventions](https://learn.microsoft.com/en-us/cpp/build/arm64-windows-abi-conventions). Ordinary calls use AAPCS64 registers and aggregate rules. Variadic calls pass floating-point and aggregate bits through the integer argument sequence. The emitter never uses the reserved x18 register. Generated functions preserve frame chains and probe each allocated stack page.

Windows ARM64 unwind records follow Microsoft's [exception handling format](https://learn.microsoft.com/en-us/cpp/build/arm64-exception-handling). Full `.xdata` records describe the prologue and each epilogue. Probe stores are represented by unwind no-ops. The compiler fails rather than truncating records that exceed the format limits.

Object generation, independent linking, assembly roundtrips, and unwind decoding can be checked from Linux. They do not prove operating-system execution. The cross-runtime suite also executes the host target, including threads, atomics, floating remainder, panic, and defer. GitHub's [runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) provides `macos-15-intel` and `windows-11-arm` for native execution qualification.

Linux RV64 uses the [RISC-V ELF psABI](https://riscv-non-isa.github.io/riscv-elf-psabi-doc/) LP64D calling convention and [RV64 ISA](https://docs.riscv.org/reference/isa/unpriv/rv64.html). Objects contain RV64IMAFD instructions, no compressed instructions or relaxation requirements, and ELF double-float ABI flag 4. GP and FP argument banks are classified independently; mixed aggregates use the hardware floating-point convention when their shape and available registers permit it. Integer arguments narrower than XLEN extend through 32 bits before sign extension to XLEN. Variadic arguments use the integer convention. The runtime preserves the LP64D integer and floating callee-saved registers for panic/defer unwinding; gp and tp remain untouched.

RV64 qualification includes QEMU execution of debug/release C aggregate calls, indirect calls, callbacks, register exhaustion, threads, atomics, floating remainder and panic/defer. `tests/aggregate-abi.py --riscv` uses Clang only as an independent test oracle; production runtime assembly and linking use the repository implementations. `tests/riscv-linker.py` separately checks relocation forms and dynamic-loader execution when `DYN_RISCV_SYSROOT` points at an LP64D sysroot.

The Windows ARM64 runtime provides `__chkstk` for external compiler objects, using Microsoft's custom allocation-size-in-x15 convention. The helper preserves SP and x15, uses only x16/x17, and probes every crossed page before the caller allocates its frame.

The explicit external-linker escape hatch selects the requested x86-64 or ARM64 Darwin architecture. External linking for Windows ARM64 currently fails with an explicit unsupported diagnostic; use the built-in linker. Windows ARM64 functions that exceed the unwind format's one-MiB function-length or unwind-code capacity fail with a format-limit diagnostic.

Windows ARM64 loader policy is checked independently against LLD-generated ARM64 images: OS/subsystem version 6.0, NX-compatible code, and dynamic/high-entropy base flags for executables and DLLs. Microsoft's [`/DYNAMICBASE` documentation](https://learn.microsoft.com/en-us/cpp/build/reference/dynamicbase) explicitly disallows disabling ASLR on ARM64. Consequently ARM64 executables, as well as DLLs, carry DIR64 base relocations for absolute image pointers. `tests/arm64-coff.py` checks these headers and relocation records under sanitizers; successful parsing alone does not replace execution on the Windows ARM64 runner.

ARM64 COFF `PAGEBASE_REL21` uses an implicit **byte** addend in the input ADRP instruction. The linker adds it to the symbol address before calculating the final page displacement; interpreting it as pages misaddresses Clang-generated local constants. The regression assembles a local constant beyond a page boundary and verifies the resolved address against LLD's [`applyArm64Addr`](https://github.com/llvm/llvm-project/blob/main/lld/COFF/Chunks.cpp) behavior.
