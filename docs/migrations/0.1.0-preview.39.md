# Removing union types

Preview 39 removes `union` types. A `union` declaration now fails with
"union types were removed; use #bitcast or a payload enum". `union` stays a
reserved word, so it still cannot be a name. Upgrade the compiler and the
editor grammar together; tree-sitter-dyn no longer parses `union` declarations.

## Reinterpreting a number's bits

```dyn
// Before
union Word { bits: u64, number: f64 }
w: Word
w.number = 1.0
print(w.bits)

// After
number: f64 = 1.0
print(#bitcast(u64, number))
```

`#bitcast` needs two numbers of the same size. It never takes pointers.

## Storing one of several shapes

Use a payload enum. It keeps a tag, so a `case` reads only the shape that was
stored. The first variant has no payload, so zeroed storage is valid:

```dyn
enum Value {
  None,
  Int: i64,
  Real: f64,
}
```

## Matching a C union's layout

Declare a field with the union's size and alignment, using its largest member's
alignment. For example, `in6_addr` is 16 bytes with 4-byte alignment:

```dyn
struct In6Addr { words: [4]u32 }
```

Read other views of the bytes with `#bitcast` on same-size numbers, or by
copying bytes. `tools/dyn-bind.py` already treats C unions as opaque.

## Rollback

Use the previous source revision with preview 38 and the matching editor grammar
(tree-sitter-dyn `4e828443`).
