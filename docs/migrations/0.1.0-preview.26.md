# Upgrading to 0.1.0-preview.26

This upgrade guide covers the compiler and SDK changes from preview.25 to
preview.26. Upgrade the compiler, SDK sources, generated bindings and editor
grammar together. Existing programs require source changes.

## Upgrade safely

Keep the previous compiler, SDK and source revision together for rollback.
Build in a separate output directory with the preview.26 compiler and its matching
SDK; do not compile new SDK sources with preview.25. Check `dyn version`, rebuild
native adapters against the matching runtime objects, and restart language
servers. When packages are available, use their verified checksums rather than
renaming an older development archive.

## Arena handles and ownership

Constructors now return `*mem.Arena`, not an arena value:

```dyn
use "std/mem"

fn main() {
  arena := mem.arena_create(0)
  defer mem.arena_release(arena)
  values := mem.push_array(u64, arena, 4)
  values[0] = 42
}
```

Pass this handle directly. Remove `&arena` only when `arena` already holds an
arena pointer; keep address operators on ordinary structs and mutable slices.
Replace embedded `mem.Arena` owner fields with `*mem.Arena`. A nil handle is
absent and does not initialize itself. Use `arena_create(0)` explicitly for the
target default. Do not copy `arena.*`.

`arena_create(block_size)` selects a preferred backing-block size, including
its header; it is no longer a hard total capacity. Owned arenas chain blocks
without moving existing independent allocations. Use
`arena_create_bounded(block_size, limit)` for a total backing limit, including
headers. A growing `mem.append` slice can move when it outgrows a block:
reacquire views and element pointers after appending. Its allocation must remain
the arena's newest allocation.

`arena_release` invalidates an owned handle, including its header. Do not release
or inspect that pointer twice. For an ownership transfer, assign the pointer to
its new owner and set the old owner to nil. The separate `GrowingArena` and
`arena_take` APIs are removed. Close files and join threads before reclaiming
their storage.

### Fixed buffers and marks

The header lives in backing storage. Currently `ArenaHeader` is 144 bytes;
arbitrary alignment requires up to 15 additional bytes. Use the public constants
rather than hardcoding those sizes:

```dyn
storage: [64 + mem.ArenaBufferOverhead]u8 = []
scratch := mem.arena_from_buffer(storage[..])
```

This guarantees at least 64 payload bytes. A too-small backing buffer panics at
construction. Buffer arenas and subarenas remain fixed; ordinary producers panic
on exhaustion. Fallible allocation remains available through `arena_try_push`
and typed `try_push` helpers.

Marks include arena bookkeeping and begin at `arena_start(arena)`, not zero.
Save `arena_mark` before an operation; use `arena_used` for payload/padding use.
Rewind/reset invalidates reclaimed views and releases later owned blocks; reset
retains the first block. Do not overwrite the header in overlap/canary tests.

For bounded raw native C scratch, use `c.string_into(destination, source)`.
It preserves exact caller-buffer capacity without inserting an arena header.
Retained C strings use `c.string_from_bytes(arena, source)`.

See [pointer and chained arenas](arena-handles-20261025.md) and the current
[buffer contracts](../guide/buffer-contracts.md). Older dated migration examples
using `&arena` must also receive this pointer-handle migration.

## Source syntax

- Replace prefix casts with `#cast(T, expression)` and
  `#bitcast(T, expression)`. Preserve the original operand boundary:
  `#cast(i64) a + b` becomes `#cast(i64, a) + b`.
- Start each statement on a separate line, including inside `defer` blocks.
  Remove commas separating `case` arm blocks.
- Write function types as `fn(i32) i32`. `*fn(i32) i32` now means a pointer
  to a function value. A function name is its value; replace `&callback` with
  `callback` when passing the function itself.
- Out-of-range contextual literals are errors, including negative unsigned
  literals and generic instances. Exact integer literals can be used in float
  contexts.

See [casts](cast-syntax.md) and [function types](function-types.md). Regenerate
bindings with the matching tools; do not blindly remove all pointer operators.

## Standard-library calls

Variable-size producers take `arena: *mem.Arena` first. Remove caller output
buffers and size-query companions where the API has migrated. This includes
string/codec/JSON producers, flags parsing, regex compilation, DNS answer
collections, complete HTTP exchanges, process capture and AEAD outputs.
Fixed-size primitives, streaming transfers and documented raw ABI scratch keep
caller buffers. A former recoverable output-capacity path is not preserved merely
by wrapping its old buffer: allow header space and decide whether exhaustion
should panic or be handled through an explicit bounded adapter.

Most single-payload edge results use `value`, `ok`, portable `kind` and native
`error`. Parser results add `offset`; module diagnostics use `detail` and provider
diagnostics remain separate. Always test `ok`: native error zero can still
describe failure. JSON and Metadesk retain `root`, not `value`, and failed parses
return read-only stubs. Use `json.is_missing` for lookup absence, distinguishing
it from explicit JSON null; linked-list termination still uses nil.

Other important changes:

- Stateful I/O/scanners retain the first failure and suppress later I/O.
  INI no longer resumes after malformed lines.
- Search positions are `usize`; a miss, including `sort.search`, returns the
  input length. Replace old negative-position checks.
- Flags results expose `value.values` and `value.positionals`. Regex `Program`
  owns arena-backed reusable workspace; copies share it, and captures expire at
  the next operation on that program.
- Thread creation takes an arena and returns a stable `*Thread` in `value`.
  Keep its arena, context and borrowed stack alive until successful join.
- Clock, sleep, deadline, profiling and benchmark operations return structured
  failures; duplicate `try_*` clock APIs are removed.
- Process capture grows arena-backed output; explicit policy limits replace
  implicit caller-buffer limits. HTTP/WebSocket control operations return
  structured results; WebSocket protocol event classification uses `detail`.
- Containers use caller-owned intrusive nodes. `mem.Pool`, `mem.FreeList` and
  `std/container/string_map` are removed.

See [std corrections](std-contracts-20261024.md),
[result shapes](result-shape.md), [typed reads](typed-reads.md) and
[containers](containers.md). The current [std guide](../guide/std.md) and source
signatures take precedence over older dated examples.

## Tooling, math and embedded support

`dyn build --emit-ir` emits versioned structural Dyn IR, not LLVM IR. Existing
consumers must use the documented new format. Standard math includes vectors,
matrices, quaternions and ranges; supported trusted operations can use native
instructions, with portable implementations retained for unsupported targets.
Sampled accuracy tests do not establish a global transcendental error bound.

RV32 and Thumb hard/soft targets have expanded release SSA coverage with tree
fallback for policy or unsupported shapes. Embedded support remains experimental.
Emulator execution, instruction audits and board-profile checks do not establish
physical-board qualification. NUCLEO hardware execution remains a separate
milestone. See [bare-metal support and limits](../guide/bare-metal.md).

## Before adopting the candidate

Rebuild dependencies and native adapters, run application tests in debug and
release, and check ownership transfer, rollback, fixed-buffer bounds and missing
JSON fields. Measure performance with matched compiler/SDK/runtime versions and
the same inputs. Compiler CI success does not prove that an application's API
migration, responsiveness or every target's runtime behavior is unchanged.
