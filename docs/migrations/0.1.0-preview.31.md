# Upgrading to 0.1.0-preview.31

This guide covers the changes from preview.30 to preview.31. Upgrade the
compiler, SDK sources and editor grammar together, then restart language
servers. Existing programs need source changes: most old forms fail to compile
with an error that names the fix, so build first and work through the errors.
The sections marked "compiles, but check" list the changes that still compile.

Three earlier notes cover parts of this release in more depth:

- [Pre-freeze language changes](prefreeze-language.md): wrapping integers,
  `#slice`, `#offset`, `union`, saturating float casts.
- [One result shape](result-shape.md): `{ value, failure }` results and
  `io.Transfer`.
- [Language rules, 2026-11-08](language-rules-20261108.md): type patterns
  without `is`, parentheses around bitwise comparisons, comparison chains,
  `io.println`, field defaults, enum tags, shadowing.

## Entry point

`main` takes no parameters. Return `i32` for an exit code. A program that wants
its arguments, or an arena that lives as long as the program, calls
`process.start()` on its first line:

```dyn
use "std/io"
use "std/process"

fn main() i32 {
  program := process.start()
  for arg in program.args[1..] {
    io.println("{}", arg)
  }
  return 0
}
```

| Old | New |
| --- | --- |
| `fn main(init: process.Init)` | `fn main()` and `program := process.start()` |
| `init.arena`, `init.args` | `program.arena`, `program.args` |
| `process.Init` | `process.Program` |

`dyn run hello.dyn -- a b` passes `a` and `b` and returns the program's exit
code. `dyn run`, `check`, `build` and `fmt` take a single `.dyn` file as a
module of that one file; other files beside it are not loaded. The language
server treats such a file the same way when its directory has no `main.dyn` or
`dyn.project`.

## Integer conversions

Implicit conversions are the ones that are lossless on every target, counting
`usize` and `isize` as anywhere from 32 to 64 bits.

| Conversion | Now |
| --- | --- |
| `usize` to `u64`, `u32` to `usize` | Implicit |
| `u32` to `isize` | Needs `#cast(isize, x)`: it loses on 32-bit targets |

Code that built for 64-bit targets only may now report a mismatch. Add the
`#cast` where the narrowing is intended.

## Maps

`map.init(&m, arena)` takes no functions. Integer, enum, bool, pointer and text
keys hash and compare by value, text by content. Another key type is a compile
error at your `map.init` call, which names `map.init_with`.

| Old | New |
| --- | --- |
| `map.init(&m, arena, hash, equal)` | `map.init_with(&m, arena, hash, equal)` |
| A seeded map | `map.init_seeded(&m, arena, seed)` or `map.init_seeded_with` |

## Generic code

- `#assert` works in function bodies and is checked once per instance.
  `#typeof(T).kind` and the other scalar fields are compile-time constants, and
  an `if` on a constant keeps only the branch it takes.
- `f(T)` with only the leading type arguments is that instance as a function
  value: `hash := key_hash(u32)`.
- A type conflict in a generic call names the argument that fixed the type:
  "T is u32 from `&names`, but this argument makes it []const u8".
- An error inside a std instance is reported at your call, with the std line
  as a note.

## Compiles, but check

- Executables keep only what `main` reaches, in debug builds too. A debugger
  can no longer call std functions the program never uses, because they are
  not in the binary. A global whose initializer could have an effect (a call, a
  division, an index or a dereference) is still kept and still runs.
- `--opt-level 3` on x86-64 and AArch64 runs counted `f32`, `f64` and `i32`
  loops several iterations at a time. Results match the scalar loop bit for bit,
  runtime checks fail at the same index after the same writes, and arrays that
  overlap take the scalar loop. Timing-sensitive code may run faster.
- On AArch64, small struct copies to addresses the compiler cannot prove
  aligned become ordinary stores, as on x86-64. AArch64 allows unaligned
  ordinary loads and stores; only code that relied on an alignment fault would
  notice.
