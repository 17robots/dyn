# Migrating to Dyn 0.1.0-preview.16

Preview 16 introduces breaking allocation API changes, primitive `Allocator`, typed
allocation builtins, constant fixed-array extents, and arena/std improvements.
Upgrade the compiler, std, runtime and language server together using the full SDK.
Do not mix the new compiler with an older std installation.

## 1. Preserve allocation failure policy when renaming

Ordinary allocation names now return failure. `_or_panic` explicitly chooses a
fatal allocation failure. Apply these replacements simultaneously, not as a
sequence that renames already-migrated calls again.

| Previous spelling | Same-behavior replacement |
| --- | --- |
| `mem.arena_try_push` | `mem.arena_push` |
| `mem.arena_push` | `mem.arena_push_or_panic` |
| `mem.arena_try_push_uninit` | `mem.arena_push_uninit` |
| `mem.arena_push_uninit` | `mem.arena_push_uninit_or_panic` |
| `mem.arena_try_sub` | `mem.arena_sub` |
| `mem.arena_sub` | `mem.arena_sub_or_panic` |
| `mem.growing_try_push` | `mem.growing_push` |
| `mem.growing_push` | `mem.growing_push_or_panic` |
| `mem.pool_try_acquire` | `mem.pool_acquire` |
| `mem.pool_acquire` | `mem.pool_acquire_or_panic` |
| `mem.free_list_try_alloc` | `mem.free_list_alloc` |
| `mem.free_list_alloc` | `mem.free_list_alloc_or_panic` |
| `mem.pool_init` | `mem.pool_init_or_panic` |
| `mem.free_list_from_arena` | `mem.free_list_from_arena_or_panic` |

New ordinary `pool_init` and `free_list_from_arena` return result structures.
Pool/free-list acquisition returns nil on exhaustion. Arena pushes return
`Allocation`; inspect `ok` before using `memory`. No compatibility aliases are
provided for removed `try_` names.

For users of the unreleased source implementation preceding this release:

| Previous source spelling | Same-behavior replacement |
| --- | --- |
| `#try_alloc`, `#try_alloc_slice` | `#alloc`, `#alloc_slice` |
| `#alloc`, `#alloc_slice` | `#alloc_or_panic`, `#alloc_slice_or_panic` |
| `#try_alloc_uninit`, `#try_alloc_slice_uninit` | `#alloc_uninit`, `#alloc_slice_uninit` |
| `#alloc_uninit`, `#alloc_slice_uninit` | `#alloc_uninit_or_panic`, `#alloc_slice_uninit_or_panic` |
| `mem.arena_try_push_array` | `mem.arena_push_array` |

Do not mechanically replace bool, nil, parser diagnostics, or native I/O errors
with allocation results. Those operation-specific interfaces remain useful.
The suffix convention does not imply that other functions cannot panic on
invalid pointers, bounds, invalid rewinds, double-free, or other misuse.

## 2. Adopt typed allocation where useful

Existing explicit size/alignment APIs remain supported. A typed object or slice
can now avoid repeating its layout and casting raw storage:

```dyn
use "std/mem"

struct Player { health: i32 }

fn main() {
  backing: [4 * mem.KiB]u8
  arena := mem.arena_from_buffer(backing[..])
  output := mem.arena_allocator(&arena)

  result := #alloc_slice(Player, output, 16)
  if !result.ok { #panic("player capacity unavailable") }
  for *player in result.value { player.* = Player{ health: 100 } }
}
```

`Allocator` is the value type, with no `#` prefix. `#allocator(context, &callback)`
constructs one; ordinary callers normally use `mem.arena_allocator` or
`mem.growing_allocator`. It allocates no storage and borrows its context.

`#AllocResult(*T)` or `#AllocResult([]T)` names the result type, whose fields are
`value`, `error: AllocError`, and `ok: bool`. `#alloc_or_panic` returns `*T` directly;
`#alloc_slice_or_panic` returns `[]T`. Typed slice allocation checks size overflow.
A zero-count request skips the callback but still requires an initialized handle.

Default allocation zeroes bytes. It does not evaluate struct field defaults.
Assign a struct initializer when those expressions matter. `_uninit` provides
no initialization guarantee: initialize every field before reading it. Preserve
uninitialized allocation in sparse mappings or large partially used buffers;
changing it to zeroed allocation can eagerly touch gigabytes of storage.

Keep raw allocation for runtime-sized opaque native layouts or stronger alignment
requirements. `#alloc_slice(u8, ...)` requests alignment 1, not a stack's or native
provider's alignment. `Allocator` and allocation results are not C ABI values.

## 3. Keep lifetime operations on concrete owners

Fixed arenas remain the default recommendation. Growth is explicit; bounded
growing arenas cap requested backing bytes, including block metadata/alignment.
Reset retains backing for reuse; trim releases eligible empty blocks; release
ends ownership. Pools and slot maps retain individual reuse/handle semantics.

An `Allocator` has allocation only: no generic free, reset, rewind, remaining-size
query, synchronization, reference counting or automatic cleanup. Helpers needing
rollback must keep their concrete arena parameters. Fixed/growing adapters use
uninitialized allocation internally so default builtins zero payloads once.

Use `arena_take(&old)` for an intentional descriptor transfer: it clears the old
slot and preserves payload addresses. Create allocator handles after the owner
reaches its final address. Existing handles do not retarget when a descriptor or
containing struct moves. Copying a handle shares its context; copying a mutable
arena descriptor duplicates its cursor and requires ownership review.

Existing local escape/owner/reset diagnostics remain deliberately limited.
Successful checking is not proof of lifetime safety. No borrow checker, GC or ARC
is introduced. Release/join failures must retain cleanup ownership; do not clear
bookkeeping or reuse storage until cleanup succeeds or a deliberate terminal
failure policy applies. Native library cleanup remains the application's job.

## 4. Std additions and constant arrays

- `mem.KiB`, `MiB`, `GiB`, checked `size_for`, and `arena_push_array` make sizing
  explicit and readable. Units do not prescribe application capacity budgets.
- Fixed arrays accept supported compile-time constants/arithmetic such as
  `[4 * mem.KiB]u8`. Runtime-sized stack arrays are not supported.
- `strings.clone_alloc` and `strings.join_alloc` accept allocator output. Existing
  concrete arena variants remain. `join_alloc` cannot rewind capacity on detected
  overlap; use `join(arena, ...)` where that rollback matters.
- `ini.parse(output, source)` validates syntax before allocating its entry table.
  Entries still borrow source text; keep both input and table backing alive.
- `strings.Result` gains allocation detail; strings and INI gain error categories.
  Review exhaustive enum matches in downstream code.

## 5. Compiler, grammar, and editor versions

The SDK uses its matching pinned grammar. Custom Tree-sitter consumers should pin
`0cc9d798858f5ceb7659fac61e12ac3a62d547cd` or a compatible descendant and regenerate
with Tree-sitter 0.25.8 when modifying grammar source. Parsing and semantic checking
are separate: the compiler decides which array expressions and callbacks are valid.

The merged dyn-editors integrations recognize the new builtins. Independently
installed language bundles, including DNA's registry, require their own grammar
and highlighting-query updates. The grammar archive's legacy Helix query does not
yet list the new builtin tokens; use the updated dyn-editors query or update that
query explicitly. A grammar update alone does not upgrade `dyn lsp`.

## 6. Older examples and DNA

Some outer-workspace examples still use `terminal.stdin/stdout/stderr`; their
replacements are `io.stdin/stdout/stderr`. This cleanup predates allocator changes.
Do not interpret those errors as allocation failures. The WASI combination of
`std/os/wasi` and standard streams also has a separately identified duplicate
foreign-symbol issue; this release does not claim to fix it.

For the audited DNA source, the required name migration is 57 callsites: 37
uninitialized panic allocations, 16 zeroed panic allocations, and four fallible
pushes. Counts describe the audited revision, not a universal migration script.
Preserve sparse document storage, operation-specific failures, native allocation
callbacks needing realloc/free, and concrete scratch/worker owners. Review owner
copy warnings and release/join failure paths before claiming runtime equivalence.

## 7. Validate and install

Download the full SDK for your platform from the preview 16 release. Its release
notes provide a mise configuration with verified per-platform SHA-256 checksums.
Restart editor language servers and verify `dyn version` reports preview 16.
Update project pins deliberately; this release does not modify downstream projects.

After migrating, run semantic checks and debug/release tests. Exercise capacity
failure, reset/reuse, cleanup retry, and custom callback behavior. Applications
with sparse mappings need resident-memory regression checks; GUI/audio/threaded
applications also need their native workflow tests. Compiler/native SDK release
gates do not substitute for downstream application qualification.
