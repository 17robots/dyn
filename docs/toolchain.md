# Toolchain and generated sources

Grammar generation and the corpus gate require **Tree-sitter CLI 0.25.8**.
The generated parser uses language ABI 15. CI installs the matching Tree-sitter
C runtime 0.25.8; this cleanup was also tested with runtime 0.26.9. An older
runtime supporting only ABI 14 cannot load this parser.

The compiler uses LLVM's C API. CI is pinned to Ubuntu 24.04 and LLVM 19;
local validation for the September 2026 cleanup used LLVM 22.1. Set
`LLVM_CONFIG=llvm-config-19` (or your installation's executable) to select its
headers and shared linker flags. When llvm-config is absent, Make uses system
headers and `-lLLVM`; that fallback requires a matching development installation.
Cross-target runtime assembly also requires Clang and the target linker tools.

`just test-grammar` runs the corpus, regenerates into a temporary directory,
compares generated bytes, and compares the local Zed copies and recorded hashes.
`just editor-grammar` refreshes local editor sources and WASM. After intentional
grammar changes, review the diff and refresh `zed-dyn/grammars/provenance.json`.
Generated files remain checked in; do not hand-edit parser output.

Before publishing the editor extension, run `just verify-published-grammar`.
This checks all five source/generated files at the immutable upstream revision
in `zed-dyn/extension.toml`. On 2026-09-21 that revision was stale: grammar.js,
parser.c, grammar.json and node-types.json differed; scanner.c matched. Publish
these reviewed grammar changes upstream, then update the extension pin and
provenance together. Local equality alone does not establish published equality.
This workspace cleanup does not publish repositories or extension releases.

`just test-static-analysis` runs Clang on every compiler C translation unit and
fails on warnings or errors; `quality-c` includes this gate. Set `CLANG` and
`ANALYZER_FLAGS` to select another installation/sysroot. The lifetime follow-up
was analyzed locally with Clang 23.1.1; CI remains pinned to Clang/LLVM 19.

Process cross-platform probes use Zig 0.16.0 locally; CI now installs that version
with the release SHA-256 from the [official download index](https://ziglang.org/download/index.json).
Darwin `#link("System")` is resolved by the target SDK linker, including SDK `.tbd`
stubs, rather than requiring a real libSystem dylib on the Linux build host.
